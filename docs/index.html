The problem

Degree planning is a scheduling problem wearing a spreadsheet's clothes.

Every undergraduate has to sequence 40+ courses across up to eight semesters, honoring prerequisite chains, co-requisites, general-education domains, and per-semester credit caps — while advisors are stretched thin and most planning still happens by hand, in a PDF of last year's course catalog.

What students actually deal with

Prerequisite chains that branch and re-converge, courses only offered certain semesters, and majors that quietly change their own requirements year to year — with no single tool that reasons about all of it at once.

Why generic tools fall short

A chatbot that just talks about course plans can sound right and still be wrong — scheduling a course before its prerequisite is a factual error, not a style choice. This project treats that distinction as the whole design constraint.

What it does

Plan in plain English. Get a schedule that's actually valid.

A student describes where they are — "I'm a junior CMPSC major, minoring in Math, I've taken everything except my last year" — and the planner returns a full, semester-by-semester path to graduation that never violates a single prerequisite, co-requisite, or credit cap.

01

Conversational front door

Natural-language input handles class standing, transfer credit, completed courses, and major/minor changes — no forms, no dropdown maze.

02

Provably valid schedules

Every plan is generated by a rules engine that checks prerequisites, co-requisites, and credit limits directly against the real course graph — not inferred from text.

03

Majors, minors, and both at once

A second major or a minor merges into the primary plan, widening shared requirements in place so a course that satisfies two programs counts for both — instead of duplicating it.

04

Built on the real course catalog

Every course, prerequisite, and requirement is scraped and verified against Penn State's live bulletin — across 161 majors and 101 minors, not a handful of demo programs.

How it's built

The AI writes sentences. It never writes the schedule.

The single decision that shapes this whole system: language models are excellent at understanding what a student means and phrasing a clear reply, and unreliable at guaranteeing a scheduling constraint holds across 40 courses. So the architecture never asks an LLM to do the second thing.

Input
Chat message
Free-text: standing, completed courses, major/minor changes, constraints.
→
Language layer
Intent parsing & reply phrasing
Extracts structured facts from the message; later phrases the response in plain language.
→
Deterministic core
Scheduling engine
Pure rules: prerequisite graph, credit caps, gen-ed domains. Same input, same output, every time.
→
Output
Verified plan
A semester-by-semester schedule, guaranteed prerequisite-safe before it's shown.

The LLM sits on both edges of the pipeline. Correctness never passes through it.

Why it's real engineering

The judgment calls that don't show up in a demo.

✓

Deterministic core, LLM UX layer

Scheduling correctness is a rules problem, not a language problem — the architecture keeps them separate on purpose, so a model hallucination can degrade phrasing but never produce an invalid schedule.

✓

Real data, verified against the source

Every course and requirement traces back to Penn State's live bulletin, checked at build time — no placeholder majors, no invented prerequisites, across 161 real programs.

✓

A test suite that actually gates changes

750 tests, including full-plan simulations that walk a synthetic student to graduation, run before anything is treated as done — not written after the fact to pad coverage.

✓

Schema that grows without breaking

Multi-campus offerings, shared major/minor credit, and bulk course completion were all added as additive extensions to the data model — every one of the 230 existing plan files kept working, unmodified, the whole way through.
